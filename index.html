Counting rules

  • JSON and YAML: null counts only real null values. The text "null" inside a string is not null. Empty string is "", empty array is [], empty object is {}.
  • XML: there is no native null. An element counts as null only when it has xsi:nil="true". An empty element has no child nodes or only whitespace, as in <a></a> and <a/>. Whitespace-only text nodes are reported separately.
  • Java-style: null is the bare token null. Empty strings are "" or ''. Empty collections are [] or {}. Empty objects are Name{} or Name().
  • Statistics that do not apply to a format show N/A. A count of 0 means there were none.
  • Paths look like $.users[0].name (JSON, YAML, Java-style) and /root/customer/name (XML).

Limitations

  • Duplicate JSON keys are found with a custom tokenizer, because JSON.parse silently keeps the last value.
  • YAML: js-yaml does not keep comments, and anchor names are regenerated, so the output is rebuilt from the parsed data. Key order is kept, except whole-number keys (such as 10:), which JavaScript lists first.
  • XML to JSON is lossy for mixed content, namespaces and repeated elements. JSON to XML needs a single root and valid element names.
  • Java-style support covers common toString() patterns only. Ambiguous or unsupported input is reported, not guessed. Input is never evaluated as code.
  • Large inputs are processed on the main thread with debounce. Above a size threshold, Auto mode pauses and asks you to use Manual mode.

Libraries

  • AngularJS 1.8.3
  • CodeMirror 5.65.16 (javascript, xml, yaml modes; searchcursor and placeholder addons)
  • js-yaml 4.1.0
  • All from cdnjs. No data is sent anywhere.
